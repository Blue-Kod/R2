## Обзор проекта

R2 - это система управления роботом, созданная для Orange Pi 4 Pro, предназначена для Д/У через WebXR и сайт.

## Веб-интерфейс

Панель управления — единое рабочее пространство с перетаскиваемыми панелями:
их можно группировать во вкладки, делить и закрывать (движок Golden Layout).
Доступны раскладки **Пульт**, **Отладка**, **Файлы**, **Сбор**; текущая
сохраняется в браузере. Командная палитра — `Ctrl+K`.

Панели: Видео, Сервоприводы, IK, Терминал, Логи, Python, Система,
Калибровка, Сбор данных, Файлы. Страница `/webxr` — телеоп в шлеме
(нужен HTTPS).

## Камера

Робот работает с Orbbec Astra Mini S (USB 2.0, одна цветная камера +
структурированный ИК-подсвет для глубины). Цвет и глубина приходят через
Orbbec SDK v1: `robov_core/orbbec_camera.py` грузит библиотеки из
`robov_core/vendor/orbbec/<arch>` через ctypes, поэтому сборка под Python
не нужна. Глубина выровнена по цветному кадру, единицы — миллиметры.

Панель «Видео» показывает переключатель **Цвет / Глубина** (у моно-камеры
нет левого/правого глаза). Глубина — монохромная, фиксированная шкала
0.2…2 м: ближе — светлее, дальше — темнее. Дыры (0) заполняются глубиной
ближайшего валидного пикселя: ближняя граница Astra (~0.5 м) больше не
даёт чёрных провалов. Под курсором — и в цвете, и в глубине — постоянно
показывается расстояние в миллиметрах (`GET /api/depth?x=…&y=…`);
значения из заполненных дыр помечены `~`. Точки `depth()` и `coords()`
тоже считаются по заполненной карте.

Один раз после подключения камеры (root):

```bash
sudo tools/setup_orbbec.sh
```

Скрипт ставит udev-правило и `usbfs_memory_mb=128`. Проверка без панели:

```bash
.venv/bin/python tools/test_orbbec_camera.py
```

Глубина в точке отдаётся со статусом:

- `0` — измерена;
- `1` — данных по камере нет вообще;
- `2` — точка в дыре, глубина неизвестна (оценка по соседям);
- `3` — то же, но оценка в ближней зоне (< 800 мм).

`depth(x, y, get_status=True)` и `coords(x, y, get_status=True)` возвращают
пару `(значение, статус)`; по умолчанию — только значение.
`GET /api/depth` возвращает `{mm, status}`, панель показывает `~` для
статуса 2 и `≤` для 3.

Температуру камеры панель «Система» не показывает: у Astra Mini S
`OB_STRUCT_DEVICE_TEMPERATURE` не поддерживается (`Property is not
supported`), SDK не отдаёт ни одного температурного поля.

Если Orbbec не найден, код откатывается на старый stereo/V4L2-путь
(`camera_backend` в `cam_params.json`). В симуляции без камеры — как
раньше, синтетический кадр.

## Режим симуляции

Запуск на любой машине — без root и без железа:

```bash
.venv/bin/python launcher.py --simulation   # или напрямую:
.venv/bin/python main.py --simulation
```

Лаунчер в этом режиме ничего не меняет в системе (нет обновлений,
пакетов, автозагрузки). Сервы принимают команды в память (I2C/PWM
не трогается); если настоящей камеры нет — синтетический кадр с
надписью SIMULATION. Порты панели: 8080 (http, редирект) и 8443
(https). Выключение, перезагрузка и обновление из панели отключены.
Эпизоды сбора пишутся в обычную `library/`.

## Конфигурация серво (единый источник правды)

Все «серво-факты» — каналы, их имена, оффсеты, инверсия, физические и
командные лимиты, поза покоя (`REST_POSE`) и поза включения (`START_POSE`) —
определяются **только в `robov_core/servo.py`**. Остальные модули берут их
оттуда: `arm_kinematics` (поза старта, маппинг), `data_collector`, `high_level`,
dev-скрипты. Для фронтенда `servo_config()` отдаётся через
`/api/bootstrap` (объект `servo`), и браузер не хранит собственных копий имён
и диапазонов.

Текущая механика: 4 сервы на каналах PCA9685 0–3 через редуктор 3:1 качают
одну ось плеча. Логический канал один — 0…90°, физически сервы едут
1…269° (на градус от упоров, чтобы не гудеть); каналы 0/1 зеркально,
2/3 прямо; импульсы 498…2686 мкс (102…550 отсчётов при 50 Гц;
2500 мкс не хватало до полного хода). Поза покоя — 0°.
Калибровка — на каждую из четырёх серв
отдельно. `arm_kinematics` (IK) и `/webxr` (телеоп) пока шаблоны: новая
геометрия ещё не описана.

### Стиль

Тёмная монохромная тема на токенах OKLCH, шрифт Geist (self-hosted).
Дизайн-система — Tailwind v4: исходник `static/css/input.css`, собранный
`static/css/r2.css` коммитится, поэтому на роботе Node не нужен. Пересборка
после изменения классов (только на машине разработки):

```bash
tools/build-css.sh
```

Шрифты (Unbounded + Golos Text) самохостятся в `static/fonts`. Красный
(`--destructive`) — только аварийные действия; цвета камеры/синтаксиса не
трогаем.
